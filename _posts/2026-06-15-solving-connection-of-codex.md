前不久在迭代早安电台工作流的时候，我做了一个很关键的决定：**把 Coze 上跑的工作流改成本地脚本一键生成。**

这个想法本身不复杂，但有一个现实问题——**我不懂编程。**

这篇文章就记录一下我的 Codex 入坑经历，以及我是怎么借助它完成这个自动化脚本的。

## 入坑：从连不上到用起来

说真的，一开始我连怎么用 Codex 都不知道。

它需要接 GPT 模型才能跑起来，但我完全不懂配置。后来通过搜索和学习，知道了可以用 **Switch++** 和 **CCSwitch** 这类工具对它进行注入，成功连上了 DeepSeek 的模型，总算是跑起来了。

但新问题又来了：**Codex 界面里有中文选项，却怎么也切换不过去。** 研究了半天才发现，需要挂梯子连到外网的中文数据包才行。折腾完这步，顺带也解决了里面的 Computer Use 插件和 Chrom 插件不能用的问题——原来都是同样的网络原因。

到这一步，算是正式入门了。

## 第一个实战：帮同学写 OJ 题目

入门之后的第一件事，是帮别人自动写学校 OJ（Online Judge）平台上面的编程题。

想法很好——输入题目描述，Codex 自动生成代码，提交就能过。但实际上手后发现 DeepSeek 模型**没有视觉功能**，遇到题目里带图片、图表或者需要理解题目截图的场景时，效果大打折扣，明显降智。

而且还有一个现实问题：**非常费 Token。** 代码生成的 Token 命中率不高，导致大模型调用费用涨得很快。用了一段时间后感觉性价比不太行，也就没继续深入。

不过这段经历让我对 Codex 的能力边界有了清晰的认识——**它很强，但不是万能的。** 知道它适合什么、不适合什么，比学会怎么用更重要。

## 回到正题：早安电台脚本

经历了这些摸索之后，再回过头来做早安电台的自动化脚本，思路就清晰多了。

早安电台的原始工作流是在 Coze 上搭建的：配置好流程节点后，每次生成视频都需要在 Coze 上试运行，拿到结果后再手动处理草稿 ID，流程很割裂。

我想要的是：**输入一个主题，脚本自动跑完所有流程，直接生成剪映草稿。**

作为一个完全不懂代码的人，这个需求正常情况下要么请人开发，要么花时间自学。但有了 Codex，第三条路出现了。

## 我的角色：产品经理

整个过程中我没写过一行代码。我的工作方式是：

**定需求 → 提给 Codex → 测试反馈 → 迭代**

举个例子，最开始我给它提的需求是：

> "我要一个脚本，输入主题和日期，自动调用 AI 生成早安文案，然后下载视频素材，拼接成完整的剪映草稿。"

Codex 理解需求后，会生成对应的代码。我拿到脚本跑一下，遇到报错就把错误信息复制给它，它会分析原因并修复。

这个过程中**产品经理思维**帮了大忙——我不需要懂 API 怎么调、JSON 怎么拼、数据流怎么设计，但我清楚地知道自己要什么：

- 输入是什么（主题、日期）
- 输出是什么（剪映草稿）
- 中间流程怎么走（文案生成 → 素材下载 → 组装 → 导出）

能把需求描述清楚，Codex 就能落地。

## 迭代过程

这个过程不是一次就成的，大概来回了好几轮：

1. **V1：基础流程** — 能跑通，但参数硬编码，不灵活
2. **V2：参数化** — 支持输入主题和日期动态生成
3. **V3：下载优化** — 自动下载视频素材，不用手动准备
4. **V4：稳定性** — 处理各种边界情况，错误重试

每一轮都是 "我提需求 → Codex 改代码 → 我测试 → 再提需求" 的循环。Codex 就像我的专属开发人员，24 小时在线，改得飞快。

## 最终效果

脚本目前的完成度是：**从输入主题到生成剪映草稿，30 秒搞定。**

对比之前手动在 Coze 上操作好几分钟的流程，效率提升非常明显。而且脚本在本地跑，不受平台限制，想怎么改就怎么改。

## 一些思考

这次经历让我对 AI 辅助编程有了很深的体会：

**对于非技术人员来说，Codex 不只是工具，而是能力的平移。** 我不需要学 Python、学 API 文档，我只需要把自己的流程想清楚，然后描述给它。

当然这也有前提——你得清楚地知道自己要什么，并且能判断输出对不对。**产品经理式的思维方式**在这里很关键：懂业务、懂流程、能验收结果。

如果你也有类似的需求——不懂代码但想自动化一些流程——强烈建议试试这条路。不需要成为程序员，只需要成为一个**更好的需求提出者。**

下一步我计划用同样的方式把封面生成也自动化，争取全链路一键出片。到时候再分享。
